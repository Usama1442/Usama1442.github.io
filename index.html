OpsPulse Health Monitor

A monitoring app deployed on AWS with Terraform.

The problem

Servers need a simple way to report whether they are healthy, for people, load balancers and monitoring tools.

What I built

  • A Flask dashboard with live CPU, memory, disk and uptime
  • /health and /ready endpoints for probes, and a Prometheus-format /metrics endpoint
  • Unit tests, plus Dockerfile and Docker Compose setup
  • Terraform code that creates an AWS EC2 instance and security group; Nginx and Gunicorn serve the app
Terraform→AWS EC2→Nginx→Gunicorn→Flask app

What I learned

Infrastructure as code makes deployment repeatable, and destroying resources after testing is as important as creating them.

CI/CD Pipeline to Kubernetes

From a code push to an app running on Kubernetes.

The problem

Building and publishing images by hand is slow and easy to get wrong.

What I built

  • A GitHub Actions workflow that builds a Docker image on every push and publishes it to GHCR
  • Kubernetes (k3s) on AWS EC2 running the app with 2 replicas behind a NodePort service
  • Ansible to automate server configuration
GitHub→GitHub Actions→Docker build→GHCR→k3s→AWS EC2

What I learned

How each tool fits into one workflow: automating build and publish, running workloads on Kubernetes, and configuring servers with Ansible.
